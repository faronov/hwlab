# ADR 0010: nRF 802.15.4 sniffer — protocol, clock model, pcapng/TAP

Status: accepted (validated on an nRF52840 DK, USB 1915:154b)

## Context

The Nordic "nRF Sniffer for 802.15.4" firmware exposes a Zephyr shell on a USB
CDC ACM port. It is not the Wireshark extcap protocol; it is a text protocol
verified against real hardware.

## Protocol (observed)

- Commands (CRLF-terminated): `sleep`, `shell echo off`, `channel N` (11–26),
  `receive`.
- Frame line: `received: <hex> power: <dBm> lqi: <n> time: <µs since boot>`.
- The last 2 bytes of the hex are an LQI-derived pseudo-FCS (not a CRC). They
  are stripped, not validated; frames are stored with FCS type "none".
- While streaming, the shell echo, ANSI escapes and typed input can interleave
  with frame lines. The parser searches each line, strips ANSI, and counts
  malformed lines instead of failing. Commands are sent one at a time with a
  quiet period between them.
- The firmware only transmits once the host asserts DTR.
- The radio keeps receiving until `sleep`. **Closing the port straight after
  writing `sleep` loses the command** on real hardware; `Close` therefore waits
  until the stream is quiet and retries once. A hardware test guards this.

## Clock model

- Device timestamps (1 µs, since boot) give accurate *relative* timing.
- Absolute alignment maps device time to host time with a minimum-offset
  estimator (per 1 s window minima, 8-window horizon, monotone clamp, reboot
  detection when the device timer jumps back by more than 1 s).
- The unknown minimum USB transit latency is not observable, so absolute time
  is late by an unknown, probably few-millisecond constant. This is reported
  as `clock.*` metadata (latency min/mean/max, offset, drift ppm, resets) on
  the artifact and in the pcapng interface-statistics comment; it is never
  hidden. Measured on the DK: drift ≈ 70 ppm over 10 s (host vs. device
  crystal), mean transit ≈ 4 ms, max ≈ 10 ms.

## Capture format

pcapng with link type 283 (IEEE 802.15.4 TAP), nanosecond timestamps in
session time. TAP TLVs: FCS type, RSS (float dBm), channel+page, LQI. Wireshark
and tshark open it directly (verified: wpan-tap, wpan, zbee_nwk). The wall
clock start is stored in the ISB comment and the artifact metadata. Timeline
packet events carry link type 230 (no FCS) payloads and the TAP-less frame.

## Consequences

- No libpcap/cgo dependency; the writer and reader are pure Go.
- tshark is optional; without it capture still works and `decode` metadata says
  "skipped".
- The sniffer firmware must not be reflashed by hwlab.
