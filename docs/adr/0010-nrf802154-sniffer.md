# ADR 0010: nRF 802.15.4 sniffer — protocol, clock model, pcapng/TAP

Status: accepted (validated on an nRF52840 DK, USB 1915:154b); amended for transmit and DFU

## Context

The Nordic "nRF Sniffer for 802.15.4" firmware exposes a Zephyr shell on a USB
CDC ACM port. It is not the Wireshark extcap protocol; it is a text protocol
verified against real hardware.

## Protocol (observed)

- Commands (CRLF-terminated): `sleep`, `shell echo off`, `channel N` (11–26),
  `receive`.
- Frame line: `received: <hex> power: <dBm> lqi: <n> time: <µs since boot>`.
- The last 2 bytes of the hex are an LQI-derived pseudo-FCS (not a CRC). They
  are stripped, not validated; frames are stored with FCS type "none".
- While streaming, the shell echo, ANSI escapes and typed input can interleave
  with frame lines. The parser searches each line, strips ANSI, and counts
  malformed lines instead of failing. Commands are sent one at a time with a
  quiet period between them.
- The firmware only transmits once the host asserts DTR.
- The radio keeps receiving until `sleep`. **Closing the port straight after
  writing `sleep` loses the command** on real hardware; `Close` therefore waits
  until the stream is quiet and retries once. A hardware test guards this.

## Clock model

- Device timestamps (1 µs, since boot) give accurate *relative* timing.
- Absolute alignment maps device time to host time with a minimum-offset
  estimator (per 1 s window minima, 8-window horizon, monotone clamp, reboot
  detection when the device timer jumps back by more than 1 s).
- The unknown minimum USB transit latency is not observable, so absolute time
  is late by an unknown, probably few-millisecond constant. This is reported
  as `clock.*` metadata (latency min/mean/max, offset, drift ppm, resets) on
  the artifact and in the pcapng interface-statistics comment; it is never
  hidden. Measured on the DK: drift ≈ 70 ppm over 10 s (host vs. device
  crystal), mean transit ≈ 4 ms, max ≈ 10 ms.

## Capture format

pcapng with link type 283 (IEEE 802.15.4 TAP), nanosecond timestamps in
session time. TAP TLVs: FCS type, RSS (float dBm), channel+page, LQI. Wireshark
and tshark open it directly (verified: wpan-tap, wpan, zbee_nwk). The wall
clock start is stored in the ISB comment and the artifact metadata. Timeline
packet events carry link type 230 (no FCS) payloads and the TAP-less frame.

## Consequences

- No libpcap/cgo dependency; the writer and reader are pure Go.
- tshark is optional; without it capture still works and `decode` metadata says
  "skipped".
- hwlab never reflashes a sniffer on its own. Reflashing is an explicit,
  DANGER_CONFIRM `dfu_program` call against a dongle that the user has put in
  its bootloader (see below).

## Amendment: transmit and DFU (zigbee-rs radio lab firmware)

Status: implemented and tested against simulators; hardware validation pending.

Security tests (Green Power replay, bad MIC) need a radio that can inject
frames while the same port keeps sniffing. Nordic's firmware cannot transmit,
so zigbee-rs ships `tools/nrf52840-radio-lab`: a pure-Rust replacement that
keeps the Nordic text protocol and USB identity (1915:154b) and adds
transmission.

### Firmware detection

- `Setup` sends `version`. The radio lab answers
  `version: zigbee-rs-radio-lab <ver> protocol: <n> caps: <list>`. The Nordic
  Zephyr shell answers `version: command not found`, which identifies it as the
  receive-only Nordic firmware. Capture works the same with both.
- `firmware_info` (SAFE) reports what was found. `ListDevices` adds the
  `PacketInjection` capability and a `firmware` property only after the
  firmware has been identified, by a capture, `firmware_info` or `transmit`.

### Transmit protocol

- `transmit <hex PSDU without FCS> [cca] [ack] [repeat <n> <interval ms>]`.
  The radio appends the FCS. Defaults: no CCA, no ACK wait, one frame.
  `power <dBm>` sets the TX power (default 0 dBm).
- The firmware echoes every frame on air as
  `transmitted: <hex incl. FCS> channel: N power: P time: T`, then
  `tx: i/n status: sent|acked|no_ack|cca_busy|error time: T` per attempt and
  `tx_done: … result: ok|aborted` at the end. Receive resumes after each frame.
  The firmware never auto-ACKs.
- Any new command line aborts a running burst. A cancelled hwlab request
  sends an empty line.

### Guards (plugin side)

- PSDU 1–125 bytes (127 with FCS), channel 11–26, power one of the radio's
  levels (-40…+8 dBm).
- `repeat` ≤ 100; with `repeat` > 1, `interval_ms` ≥ 10 and the whole burst
  ≤ 30 s.
- Rate limit: 300 frames per rolling minute per port.
- `ack` needs a PSDU long enough to carry a sequence number.
- The method is DANGER_CONFIRM: it puts energy on a shared band.
- With a capture running on the port, transmit goes through that capture and
  must use its channel (no silent retune). Otherwise the plugin opens the port,
  transmits and puts the radio back to sleep.

### Audit

- Every accepted request is appended to
  `$HWLAB_HOME/artifacts/nrf802154-tx/audit.jsonl` *before* anything is sent
  (a failed audit write refuses the transmission), and a result record follows
  with per-attempt status and device timestamps.
- During a capture each transmitted frame is also written to the pcapng as an
  outbound packet (EPB flags direction=outbound, comment = transmit id, no
  RSSI/LQI TLVs) and emitted as a timeline packet event with `direction=tx`.
  The artifact metadata counts `tx_frames`.

### DFU

- The PCA10059 dongle has Nordic's open USB serial DFU bootloader (1915:521f),
  entered with the side RESET button. Discovery lists it as a separate device
  (`mode=dfu`, capability FlashProgramming).
- `FlashProgramming.dfu_program` (DANGER_CONFIRM, `confirm_token:
  program-application`) takes an Intel hex or an nrfutil zip. It refuses a
  `.bin`, images not at 0x1000, images reaching the bootloader at 0xE0000, and
  images with an implausible vector table. The init packet generated for a hex
  is byte-identical to nrfutil's. A zip's init packet must match the image.
- To restore Nordic's sniffer, program
  `nrf802154_sniffer_nrf52840dongle.hex` from
  NordicSemiconductor/nRF-Sniffer-for-802.15.4 the same way (or with
  `nrfutil nrf5sdk-tools dfu usb-serial`).
